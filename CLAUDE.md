# Simple Development Rules

- [me] refers to Anders, the prompter, and [you] refers to you, Claude. I will maintain a high-level direction and coordination for the program, but it is up to you to implement the code.

## 1. Safety & Collaboration

- Only interact with the github repo associated with this project
- When working on a new feature, always implement it on a new Git branch
- You may merge to main only upon review and approval
- When human user-testing is valuable for a feature, loop me in for testing and refinement; use your discresion to separate the hard-testable features from taste-based or soft-testable features, and test on your own where objective measures are reliable
- Do not hesitate to ask if you require additional permissions or for me to set up a local testing environment

## 2. Organization

- Ideally, we will merge to main after each milestone
- You may make as many commits and sub-branches as you desire as long as they stay organized and do not touch main
- Maintain a high-level bare-bones DEVLOG.md of the features implemented in each milestone
